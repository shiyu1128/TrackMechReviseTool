# TrackMechReviseTool

## 阶段开发与 GitHub 同步要求

项目采用分阶段开发。每完成一个阶段的实现与验证后，必须立即将该阶段的代码、文档和必要的测试变更提交到 Git，并同步推送至项目 GitHub 远程仓库。只有本地验证通过、提交完成且 GitHub 推送成功后，该阶段才视为完成；不得累计多个已完成阶段后再统一同步。

每次阶段同步应满足以下要求：

1. 运行与本阶段变更范围相符的构建、测试或样例验证，并记录验证结果。
2. 检查待提交内容，避免提交生成文件、缓存、临时文件或无关改动。
3. 使用能够准确说明本阶段成果的 Git 提交信息。
4. 将提交推送至 `origin/main`，并确认本地分支与远程分支一致。
5. 若推送失败，应保留已完成的本地提交，解决连接或远程冲突后继续推送；推送成功前不得宣布该阶段完成。

## 桌面应用开发版

当前 WPF 桌面应用已串联 `.out` 解析、标记元素选择、反应候选生成、分支概率编辑、`REV A/n/E` 人工输入、计划校验、完整 `.inp` 输出和标记热力学 `.dat` 输出。开发环境要求 Windows 10/11 和 .NET 8 Desktop Runtime。

```powershell
dotnet run --project src/TrackMechReviseTool.Desktop
```

基本流程：选择 `.out` 文件，选择标记元素并生成计划；在表格中确认候选分支、正逆概率和必要的 `REV` 三参数；执行“校验计划”；校验通过后输出 `.inp`。需要生成热力学文件时，还应先选择源 `.dat`。安装版 `.exe` 和安装程序将在发布阶段生成。
