# TrackMechReviseTool

## 阶段开发与 GitHub 同步要求

项目采用分阶段开发。每完成一个阶段的实现与验证后，必须立即将该阶段的代码、文档和必要的测试变更提交到 Git，并同步推送至项目 GitHub 远程仓库。只有本地验证通过、提交完成且 GitHub 推送成功后，该阶段才视为完成；不得累计多个已完成阶段后再统一同步。

每次阶段同步应满足以下要求：

1. 运行与本阶段变更范围相符的构建、测试或样例验证，并记录验证结果。
2. 检查待提交内容，避免提交生成文件、缓存、临时文件或无关改动。
3. 使用能够准确说明本阶段成果的 Git 提交信息。
4. 将提交推送至 `origin/main`，并确认本地分支与远程分支一致。
5. 若推送失败，应保留已完成的本地提交，解决连接或远程冲突后继续推送；推送成功前不得宣布该阶段完成。

## 桌面应用开发版

当前 WPF 桌面应用已串联 `.out` 解析、标记元素选择、反应候选生成、分支概率编辑、`REV A/n/E` 人工输入、计划校验、完整 `.inp` 输出和标记热力学 `.dat` 输出。开发环境要求 Windows 10/11 和 .NET 8 Desktop Runtime。

```powershell
dotnet run --project src/TrackMechReviseTool.Desktop
```

基本流程：选择 `.out` 文件，选择标记元素并点击“生成计划”。程序从当前 `.out` 实时计算组分标记态和反应候选，通过进度条显示已分析反应数；计算完成后弹出保存窗口，可命名并保存新的计划 CSV。随后在表格中确认候选分支、正逆概率和必要的 `REV` 三参数，执行“校验计划”，校验通过后输出 `.inp`。需要生成热力学文件时，还应先选择源 `.dat`。安装版 `.exe` 和安装程序将在发布阶段生成。

标记规则不按元素分别硬编码。元素下拉框来自当前 `.out` 的元素表；无论选择 N、O、H 或 C，程序均按相同算法读取各组分的元素组成、解析组分名称、枚举 `k=1...N` 的标记原子分配，并生成带 `*` 的组分和反应。名称解析出的目标元素数量必须与 `.out` 组成一致，不一致的特殊命名组分会被列为缺失规则并阻止静默写出错误机理。

反应表采用可折叠的两级目录。一级为原反应编号；二级中 `1a`、`2a` 等固定表示保留且只读的无标记原反应，`1b`、`1c`、`2b` 等表示由该原反应生成的标记候选。保存、校验和最终写出只处理标记候选，原反应由完整机理写出器直接保留。

正向和逆向概率使用按分支组动态生成的可编辑下拉框，并统一显示为约分后的分数。唯一分支提供 `1/1`；n 个竞争分支提供 `0/1` 到 `1/1` 的等分值，例如 `1/2`、`1/3`、`2/3`，并补充按组内 `gf` 或 `gr` 归一化得到的统计分数。已有小数或自定义概率会自动转换为分数显示，也可直接输入其他分数；不可逆反应的逆向概率为空且禁止编辑。内部计算仍使用数值，最终以同一分支组概率和等于 1 的校验结果为准。
